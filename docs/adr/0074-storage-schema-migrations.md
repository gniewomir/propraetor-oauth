# Storage schema migrations: embed, ensure-record, squash, version match

The single Operator binary (ADR-0019) ships Storage schema migrations via `embed`, exposed to the rest of the process as `fs.FS` from an oblivious assets package (migrations now; templates later). Callers—including `internal/adapter/postgres/migrate` and tests—depend on `fs.FS`, not on `embed`. Production migrations always come from the embedded tree; a future template-eject/disk backend may appear without changing migrate. Operator CLI surface for `--up`/`--down` and `OAUTH_STORAGE_ENV` remains ADR-0072.

The migrator is a thin internal runner (no migration library). Before any versioned SQL: ensure table `storage_schema_migrations` exists (create if absent—this is not a versioned migration and not `bootstrap-sql`). Then take a Postgres advisory lock, validate paired `NNNN_slug.up.sql` / `NNNN_slug.down.sql` files (missing twin is fatal), and apply. Versions are contiguous integers; each version runs in one transaction; `--down` moves exactly one version per invocation. Applied versions are append-only rows (`version`, `applied_at`); content checksums are deferred. Rolling down past version 1 removes applied rows but leaves the empty record table. Pre-v1 migration history is disposable: a human freeze squashes to a single baseline (old SQL files deleted from the tree; baseline becomes version `1` again); afterward migrations are append-only. `dev`/`test` databases are recreated after squash, not upgraded across rewritten history.

A process is aligned when the database’s current Storage schema version equals the highest version embedded in that binary. Version behind head is fail-closed except where ADR-0072 allows auto-`--up` in `dev`/`test`. Version ahead of head, unknown to the embedded set, holes in applied history, or other corrupt record state are always fatal. Locked migrate messages: stdout `storage: schema N` after `--up`/`--down` (including already-at-head; `N=0` when nothing applied); stderr `storage: migrate --down refused` outside `dev`/`test`; stderr `storage: migrations invalid` for bad embedded pairs; stderr `storage: migrate failed` on apply failure; bare `migrate` requires `--up` or `--down`.
