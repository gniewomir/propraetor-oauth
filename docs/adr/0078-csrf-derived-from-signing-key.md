# CSRF bound to Authorization Session via derived HMAC

Login and Consent POSTs require a CSRF token bound to the Authorization Session (ADR-0048). The token is not stored as a column. The AS derives a 32-byte HMAC key with HKDF-SHA256 from the ES256 signing private scalar (stable raw encoding, not PEM text), with HKDF `info = "propraetor-oauth/csrf-v1"`, then sets `csrf = HMAC-SHA256(csrf_key, session_handle_sha256)` for the form field and verifies with constant-time compare. Purpose separation keeps JWT signing and CSRF HMAC from sharing a raw key; the Operator still provisions only the signing PEM. Signing-key replace + restart yields a new CSRF key: in-flight sessions may still authenticate by cookie, but the next CSRF-protected POST fails until the page is re-rendered (accepted given short Authorization Session TTL and ADR-0043 rotation-via-restart).
