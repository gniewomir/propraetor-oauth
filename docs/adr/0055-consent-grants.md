# Consent Grants in Postgres

Resource Owner approval of Scopes for a Public Client is stored as Consent Grants in Postgres with composite primary key `(user_id, client_id, scope)` (ADR-0077). Incremental Consent (ADR-0011) skips already-granted active Scopes. If the Operator Disallows a Scope on a Client’s allowlist, matching Grants become invalid and the next Authorization Request requires Consent again. The Operator CLI can Deactivate Grants per End-User, per End-User × Client, or per End-User × Client × Scope (`deactivated_at`); Reactivate clears `deactivated_at` rather than inserting a new row (ADR-0075). End-User Consent UI grant may create or restore a Grant through the AS UI and is distinct from Operator Reactivate. Every Deactivate and Reactivate is audited.
